# QA and code audit — 4 October 2026

**Assessment: suitable for continued development; not ready for a public release.** The automated happy paths pass, but targeted failure testing found privacy, recovery, clipboard, and storage defects. Fix the P1 findings before expanding the feature set.

This audit covers the current working tree, including its already-staged initial implementation. Production code was not changed. The report distinguishes executed reproductions, code-inspected consequences, known open risks, and untested hardware/OS cases. It is not a claim that every possible bug has been found.

### F01 — Password protection expires after 60 seconds

**Location:** `native/flow-helper/Sources/FlowHelperCore/SecureFieldPolicy.swift:82`.

When an app's accessibility tree does not identify its password input, Secure Event Input is the remaining protection. The policy unconditionally ignores that signal after 60 seconds. Leaving a real Chromium password field focused for longer than a minute is legitimate; duration does not prove that the OS signal is stuck.

**Reproduction:** execute the production policy with `elementIsSecure=false`, Secure Input enabled and held by the frontmost app. At 59/60 seconds it refuses; at 61 seconds it allows. The existing test explicitly expects the latter behavior. A live browser password-field paste was not performed in this audit.

**Impact / repair:** dictated content can enter a protected input once this heuristic expires. Do not override an ambiguous secure-field signal based on elapsed time alone. Require independent evidence, or refuse automatic paste and offer recovery. Add a regression for a legitimately focused password input lasting more than a minute.

### F02 — Redirects bypass local-only cleanup routing

**Location:** `src/main/cleanup/ollama-client.ts:168` and `:282`.

The gate validates the configured loopback address, but chat and metadata use fetch's default redirect following. A loopback service or proxy returning HTTP 307/308 can forward the transcript POST body to a destination that was never checked.

**Reproduction:** a validated ephemeral loopback server returned 307 to a second loopback origin. The second server received the complete synthetic chat body. No user content or external destination was used. Off-machine forwarding is the consequence of the same unrestricted redirect behavior, not an external exfiltration performed by this audit.

**Repair:** reject redirects for Ollama requests, or validate every redirect before forwarding a body. Test both metadata and chat against an untrusted destination. This requires a redirecting local endpoint; it is not evidence that ordinary Ollama traffic is currently leaving the machine.

### F03 — Remote warm-up result is ignored

**Location:** `src/main/cleanup/ollama-client.ts:271` and `src/main/cleanup/refiner.ts:89`.

`warm()` discards the chat result, including its `remote` flag. Metadata can initially look local, while a warm-up response identifies `remote_host`. The refiner treats that warm-up as successful and still sends the next actual transcript. Only the later response blocks the model.

**Reproduction:** local-looking metadata, then a warm-up response containing remote metadata, then refinement. The probe counted one transcript-bearing request after remote operation had already been disclosed.

**Repair:** propagate warm-up locality and immediately block that model before any transcript request. Also bound/cancel warming and key warm state by model and server.

### F04 — Processing-stage Undo loses text

**Location:** `src/main/dictation/speech-service.ts:263`; `src/main/dictation/session-controller.ts:312` and `:417`.

Audio is released as soon as speech recognition finishes, while cleanup or subsequent processing can still be running. Cancel during that interval offers Undo even though reproduction needs the now-released recording. Clicking Undo fails with “The recording is no longer held” and overwrites the recovery entry with empty stages.

**Reproduction:** real quiet app with the existing processing-delay hook. Before Undo: recovery had text, `holdsRecording=false`, and the pill offered recovery. After Undo: failed outcome, recovery had no text, no paste. Cleaned mode naturally provides the post-transcription processing interval made deterministic by the hook.

**Repair:** reuse the produced text for Undo or retain required audio until the offer expires. A failed attempt must preserve any useful existing recovery text. Add an end-to-end assertion that actually clicks Undo after transcription; the existing processing-cancel scenario only verifies no paste.

### F05 — Clipboard timing is not bounded by the advertised budget

**Location:** `native/flow-helper/Sources/FlowHelper/PasteTransaction.swift:151`; `src/main/native/helper-bridge.ts:260`.

The snapshot's 250 ms budget is checked before a synchronous lazy-provider read. That read can block arbitrarily; the last read has no post-read deadline check. The bridge's six-second timeout merely removes the pending reply. It does not expire or cancel the helper's pending paste.

**Reproduction:** an isolated private pasteboard with a controlled lazy provider caused the exact snapshot implementation to accept a snapshot after about 605 ms. No system keys were posted. From the control flow, a read lasting beyond six seconds can finish after the app has reported failure and still post Cmd+V, if the destination still passes validation. Retrying can then duplicate the text.

**Repair:** carry a paste expiry to the helper and recheck it immediately before clipboard mutation and key posting. Prevent a blocking snapshot from producing a late action; test providers exceeding both the snapshot budget and RPC deadline.

### F06 — Partial clipboard formats are silently lost

**Location:** `native/flow-helper/Sources/FlowHelper/PasteTransaction.swift:152`.

An advertised pasteboard type whose data cannot be read is skipped with `continue`. The remaining types are returned as a successful snapshot, and restoration clears the clipboard before writing that incomplete copy.

**Reproduction:** a private pasteboard advertised two types, one unavailable. Snapshot succeeded with only one saved type. This did not touch the user's general clipboard.

**Repair:** fail the entire snapshot when any promised format cannot be preserved. Check change counts across capture and restoration write results; do not report successful restoration of an incomplete item.

### F07 — Escape from the previous session disables the new session's cancel

**Location:** `native/flow-helper/Sources/FlowHelperCore/BindingMatcher.swift:151`.

**Reproduction:** cancel with Escape but keep it held; start a new hands-free session with Fn+Space; release that chord, then the old Escape; press Escape again. The old release unconditionally clears `escapeArmed`, overwriting the new session's arm request. The production matcher probe emits no cancel and does not swallow the new Escape. Physical keyboard testing remains outstanding.

**Repair:** make arming generation-aware, or consume an arm on key-down while tracking only the old press's swallow state until key-up.

### F08 — Settings mutation is not transactional

**Location:** `src/main/store/settings.ts:53`; callers in `src/main/index.ts:112`.

**Reproduction:** make the temporary settings output unwritable in an isolated directory. `update({mode:'cleaned'})` throws `EISDIR`, but memory contains `cleaned` while disk remains `verbatim`. Callers update the tray only after that throwing operation, leaving runtime, menu, and persistence inconsistent. The same mechanism affects the evaluation-recording setting.

**Repair:** validate and persist a candidate before replacing the in-memory value; catch save errors and show a recoverable failure. Test mode, microphone, and evaluation toggles with disk errors.

### F09 — Corrupted models have no repair path

**Location:** `src/main/stt/model-store.ts:47` and `:80`; `src/renderer/hub/App.tsx:155`.

**Reproduction:** download a tiny synthetic model, then replace its bytes with equal-length zeroes. The marker and size still satisfy `isModelReady()`. Retrying `downloadModel()` makes zero fetches despite a checksum mismatch. The Hub also hides Download while files are considered downloaded, even when loading has failed.

**Repair:** invalidate verified status on changed-file metadata or load failure and expose Verify/Repair. Do not hash the entire real model on every 1.5-second status poll. Test corruption and recovery through the UI.

### F10 — Download errors wait for stalled network input

**Location:** `src/main/stt/model-store.ts:140`; `src/main/dictation/speech-service.ts:148`.

**Reproduction:** deliver a small response chunk, induce an asynchronous output write error, then stall the response. Since `write()` did not signal backpressure, the code waits for the next network chunk instead of racing the writer failure. The operation remained pending at 200 ms and immediately rejected when the stream was released. There is no download cancel control or service-provided abort signal.

**Repair:** propagate output failures to the input stream immediately; add cancellation and an inactivity timeout. Test disk failure and stalled input together, rather than independently.

### F11 — Ollama model selection depends on optional list metadata

**Location:** `src/main/cleanup/local-only.ts:98`.

`localTextModels()` requires `capabilities` from `/api/tags`. Servers omitting that optional field yield an empty picker even when `/api/show` identifies a usable local completion model. The default configured model may still work, so this primarily prevents choosing alternatives.

**Reproduction:** a tags fixture without capabilities passes `gate.check()` through `/api/show`, but returns no picker entries. Current upstream supports optional capabilities: this is a compatibility defect, not a claim that every current Ollama server fails. The [official tags example](https://docs.ollama.com/api/tags) omits the field; [upstream API types](https://github.com/ollama/ollama/blob/main/api/types.go) make it optional.

**Repair:** look up missing capabilities through `/api/show` with a bounded cache, or document/enforce a minimum response contract. Include actual documented API fixtures in tests.

### F12 — Old status responses can win a race

**Location:** `src/main/index.ts:123`.

Every `cleanupStatus()` completion updates the tray without checking which settings initiated it. Enter Cleaned while the server is slow, then switch to Verbatim or choose another model: a late response can restore the old status beside the new setting. This is code-inspected, not a timed UI reproduction.

**Repair:** use a request generation and settings snapshot; discard stale responses. Also refresh availability when an installed Ollama server starts after the menu was populated.

### F13 — Privacy and interaction descriptions are inaccurate

**Location:** `src/renderer/hub/App.tsx:142`; `README.md:7`.

The visible setup window says microphone use occurs only while the key is held and audio is not stored. Hands-free mode already records without a held key, and opt-in evaluation persists audio and text. The README says hands-free is not built, though it is implemented and exercised by the suite.

**Repair:** describe all recording modes, qualify storage behavior by the evaluation setting, and make “saving recordings” clearly visible. Update the README's implementation status.

## Existing risks that remain unresolved

These were already recorded in `docs/progress.md`; they are not presented as newly discovered live failures here.

- **Focus-stealing system panels:** Spotlight or the emoji picker can accept the paste while the recorded frontmost app remains unchanged. Resolve this before claiming destination-safe insertion.
- **Fixed clipboard restoration time:** a target reading the pasteboard after 500 ms can paste the old clipboard content. Implement the planned read receipt and distinguish “paste sent” from “paste confirmed.”
- **Physical modifier interaction:** the helper constructs paste events from `.hidSystemState`. Test a private event source across layouts and held modifiers before changing it.

One additional code-inspected risk: `Target.swift:73` compares window/element identity only when both old and new snapshots provide it. Losing previously available accessibility information is accepted as unchanged. Add a conservative fallback and tests for inaccessible or rebuilt destinations. No same-app wrong-field paste was reproduced in this audit.

## Dependency and release review

`npm audit` reports a high-severity advisory for development dependency `http-cache-semantics@4.2.0`, reached through `electron-builder → app-builder-lib → @electron/get → got → cacheable-request`. The advisory concerns shared HTTP cache response disclosure; it does not establish a runtime exploit in this app. Production-only npm audit reports zero findings. Review the build-chain exposure and compatible remediation; do not assume an automatic dependency update is safe. [Advisory GHSA-ch52-4w7c-c8xp](https://github.com/advisories/GHSA-ch52-4w7c-c8xp).

The inspected **Dev** executable retains Electron development fuses: RunAsNode, NODE_OPTIONS support, and inspector arguments enabled; ASAR integrity and OnlyLoadAppFromAsar disabled. Treat explicit fuse configuration/verification as a release gate. The valid development signature alone does not prove notarization, safe updates, supported minimum macOS behavior, or third-party binary licensing completeness.

## Improvements and enhancements, in suggested order

1. **Finish reliability and privacy first:** F01–F10, destination confirmation, paste read receipts, transactional settings, and reliable recovery. Add regression tests for each reproduced defect before fixing it.
2. **Complete practical setup/settings:** editable shortcut fallback for keyboards without Fn, dictionary editor, explicit rules-only cleanup option, installed-model discovery, microphone meter/test and device fallback notice, model repair/cancel controls, and an offer to start installed Ollama.
3. **Make recovery discoverable:** searchable history with explicit retention and deletion controls, clear Copy/Paste Last actions, and preservation of text after failed retries. Keep audio persistence opt-in and visible.
4. **Improve accessibility and discoverability:** keyboard/VoiceOver-operable start/stop/cancel controls, larger start target, shortcut hints, and visible recording/storage status. The resting pill is currently a clickable status `div` in a nonfocusable window; a full assistive-technology test is still needed.
5. **Measure actual dictation quality:** evaluate the planned 30–50 corrected personal utterances across accent/language, noise, numbers/currency, punctuation, technical names, and code. Compare Verbatim and Cleaned for meaning changes, not just word error rate.
6. **Establish a release matrix:** minimum supported macOS and current macOS; signed first launch; real permission grant/revocation; several keyboard layouts; built-in/USB/Bluetooth microphones; hardware disconnect; lid close/lock; external displays/Spaces/full-screen apps; 20-minute recordings and repeated-session memory measurements.

Persistent history, the full Hub, context awareness, Command Mode, and release distribution are planned work, not regressions in already-completed features. Keep those enhancements separate from the correctness backlog.
