# Whisper Flow

Local-first dictation app for macOS: Electron + TypeScript, one Swift helper, a local speech recognizer, optional Ollama cleanup. The design and plan are in `docs/`.

## Before starting work

1. Read `docs/tracker.md` for the current phase and what is waiting on a person.
2. Read the latest entry in `docs/progress.md`.
3. The phase definitions and gates are in `docs/03-implementation-phases.md`; verified technical facts (versions, protocols, gotchas) are in `docs/04-implementation-reference.md`.

## Working agreements

- **Keep the tracker and the log current.** Update `docs/tracker.md` (task status, gate outcomes) and add a dated entry to `docs/progress.md` (what was done, evidence, decisions, deviations) in the same change as the work. Record gate measurements in `docs/benchmarks.md`.
- **Follow the phase order and gates.** Do not build on a gate that has not been measured.
- **Product logic lives in TypeScript.** The Swift helper is OS glue only.
- **Verify before claiming.** A task is done when its check has run and passed; say which check.
- **Privacy rules are requirements:** never log transcript text; no network use beyond loopback Ollama and downloads or update checks the user starts; refuse Ollama models with remote-host metadata.
- **Licences:** adapt code only from the MIT projects listed in `docs/04-implementation-reference.md` section H, with attribution. Do not copy from GPL or AGPL projects, and copy nothing from Wispr Flow.
- **Use a well-known package rather than writing generic plumbing by hand** (request and answer pairing, retries with backoff, and the like): `birpc` and `p-retry` are examples already in use. Everything is bundled, so it goes in `devDependencies`. The About page names the main components, not every package; `tests/unit/third-party.test.ts` checks that every bundled package, and what it brings with it, is under a licence that asks for no more than its notice.

## Things that are easy to get wrong

- **Permissions in development.** Under `npm run dev`, macOS attributes Accessibility and Microphone to the terminal that started it. Test permission behaviour on the packaged build, launched with `open -n "dist/mac-arm64/Whisper Flow Dev.app"`.
- **Preloads are sandboxed** and must stay self-contained; `scripts/check-build.mjs` enforces this.
- **The capture worklet** must be imported with `?worker&url`; a plain `?url` import ships raw TypeScript.
- **electron-vite 5 predates Electron 44.** Build targets are set explicitly in `electron.vite.config.ts`, which also carries a shim for a crash when output is not a terminal.
- **TypeScript is pinned to 6.0.x** because typescript-eslint does not support 7 yet.
- **Quit Wispr Flow before testing shortcuts**; two apps tapping `Fn` will fight.
- **Someone may be using the Mac while tests run.** Four things have gone wrong this way. On 2026-10-03: a focus-taking test may have pasted test text into another app; a test app with the key tap active swallowed the user's own `Fn` presses; and an Electron app started from the terminal came to the front and took keyboard focus. On 2026-10-04 the keyboard tests ran four times over a FaceTime call: they had waited for a quiet keyboard, and someone on a call touches nothing. The rules that came out of it:
  - Prefer `npm run test:app`. It runs the app with `WHISPER_FLOW_QUIET=1` (no key tap, never comes to the front) and drives it through the debug control line.
  - `test:helper:integration` and `test:e2e` post system-wide key events and take focus. Run them sparingly, with `-- --when-idle 120`, and say so when you do. They refuse to start during a call, a video or a recording and stop when an app they did not open comes to the front (`scripts/lib/mac-in-use.mjs`); do not pass `--even-if-in-use` unless the person at the Mac asks for it. They also refuse, with no switch to override it, while another app listens to the dictation key: Wispr Flow, any Whisper Flow build (the packaged one in use included), or a from-source instance started without `--hidden`. Any new test of this kind must use the same guard, set `WHISPER_FLOW_PASTE_ONLY_INTO`, and confirm its own app is frontmost before every key press and before every window it brings forward.
  - When a keyboard test fails, find out which app was in front before suspecting the code: `/usr/bin/log show --info --start "…" --predicate 'process == "launchservicesd" AND eventMessage CONTAINS "SETFRONT"'` lists every change of the front app (`log` alone is a zsh builtin).
  - The switches are listed in `docs/04-implementation-reference.md` under "Test tools and safeguards".
- **macOS answers some permission questions once per process.** `CGPreflightPostEventAccess` asks the first time and repeats that answer for good. The helper once asked before Accessibility was granted, and then refused every paste for as long as it lived (2026-10-03). Decide on `AXIsProcessTrusted`, which follows the setting, and never on the preflight alone. The app also replaces the helper with a fresh process when the grant arrives while it is running.
- **A run that starts with permissions already granted says nothing about a first launch.** The order "start, then grant" is its own case. `test:e2e` imitates it (`FLOW_HELPER_GRANT_AFTER_MS`); only a person can do the real thing.
- **When a dictation misbehaves, read the log before guessing:** `~/Library/Logs/Whisper Flow/main.log` (tray → Show Log). It has the shortcut events, the states, the app the text was meant for, and the reason for any refused paste. How to read macOS's own log when there is none is in `docs/04-implementation-reference.md`, under "Finding out what happened to a dictation".
- **Key events posted by a program need a keyboard's pace.** Six events inside 3 ms from a process that exits at once lost their last event now and then, and a lost key-up leaves everything believing the key is held. The test tool spaces events and waits before exiting; keep that in any new one.
- **A Mac left alone goes dark, and that ends a dictation.** When the display turns off (which locks the screen) or the Mac goes to sleep, the app interrupts the session in progress, as designed. A long test run that spans either loses the scenario that was running: on 2026-10-04 one failed at the minute the display went off and another across an idle sleep. `test:app` now keeps the Mac awake while it runs (`caffeinate`), and says so when a failure coincides with such an interruption. `pmset -g log` has the times.
- **Never compare `URL.origin` for `app://` pages.** It is the string `"null"` for that scheme. Use `isOwnPageUrl` (`src/main/app-url.ts`).
- **The overlay gets its port to the speech worker only after the model has loaded.** Before that the worker would drop the frames.
- **Transcript text must never be printed**, including by tests: assert on counts and on the word error rate against text the test supplied (`expect` on the debug control line).
- **A model is never contacted before it has passed the local-only check** (`LocalOnlyGate`), not even to warm it up. Cleaned mode must always have an answer on time: whatever the model does, the rules-only text is the fallback.
- **Accessibility reads go through the frontmost app's element.** The system-wide element fails with `cannotComplete` from the helper on macOS 26.
- **Every request to Ollama goes through `OllamaClient.send`**, which never follows a redirect: the address a redirect names was checked by nobody. Do not call `fetch` for Ollama anywhere else. A model's own reply has the last word on where it runs, and that includes the warm-up's reply: a transcript waits for a warm-up that is still on its way.
- **Protection of password fields never lapses with time or history.** Apart from the documented terminal exception, Secure Input held by the app in front always refuses automatic paste. `SecureInputHistory` is diagnostic only: a background hold does not prove the current field safe. Recovery offers Copy instead.
- **A paste request carries the time the app stops waiting** (`expiresAt`). The helper does nothing to the clipboard or the keyboard after it; the order of the steps is `PasteSequence`. A clipboard that cannot be copied whole is not put back.
- **A recording is held until its session is over**, and it is the session controller that lets it go (`forgetRecording`), not the speech service: a cancel at any point before that can be undone. An attempt that ends with no text must not erase text an earlier attempt left (`RecoveryBuffer`).
- **Settings are changed through `changeSettings`** (`src/main/store/settings-changer.ts`): a change that cannot be saved is not made.
- **The interface is built from a design.** Sizes, colours and durations come from the Claude Design project named in `docs/05-design-brief.md` and are named in `src/renderer/tokens.css`. A new colour or duration is a new token there, not a value in a component. What the pill draws is worked out in `pill-view.ts` and what Home says in `home-status.ts`: both are plain functions with tests, and the components only draw.
- **A Tailwind colour and a font size must not share a name.** `text-key` was both the keycap's colour and its type size, and the colour won: the keycaps were drawn with their own background as text colour. The colour is `keycap`.
- **The window's element rules live in `@layer base`** (`src/renderer/styles.css`), so that a class on an element wins over them. Outside a layer they beat every utility whatever its specificity: the Ollama address field was never monospace, and a focus ring meant to sit inside a list was drawn outside it (2026-10-05). `.only-spoken` and the drag strip's classes stay outside any layer, so that nothing can override them.
- **Everything the pill offers is also in the menu-bar menu**, because the pill's window cannot take the keyboard. A new pill button needs its menu item, and its sentence in `spokenFor`.
- **The strip that drags the main window lies over the top 44 px of every page.** It is positioned, so it sits above anything in the normal flow there, and a button under it is drawn and cannot be clicked: "Stop saving" was (2026-10-04). Anything to click in that strip needs `relative z-10`. `press-hub` on the control line presses a button only if a click could reach it.
- **The mark for unpasted text is about the text, not about the last key press.** `PillPresenter.textTaken()` is the one thing that clears it; a recording that starts does not, because a lone tap or `Fn`+arrow starts one and drops it.
- **Cancel on the processing pill appears after a second.** A test that clicks it has to wait for it (`click-pill` does).
- **To look at the interface, take pictures of it:** `npm run pictures` (into `dist/.pictures/`). It drives a quiet instance with the control line (`capture-pill`, `capture-hub`, `appearance`, `hover-pill`), takes no focus and can run at any time. Two defects of 2026-10-04 were visible only in a picture.
- **What was said is written to disk only after a system dialog has asked.** The history is in memory unless the user chose otherwise on the History page, and `setKeep` in `src/main/hub/wire-hub.ts` is the one way to change that: it puts the question (`src/main/hub/questions.ts`) and writes nothing before a yes. The same goes for deleting. Do not add another way in, and do not let a page set what it likes: each handler there checks what it is given (a microphone the system offers, a model that runs on this Mac, an Ollama address on this Mac).
- **Nothing reaches outside the app except through a door.** Finder, the browser, the clipboard, Ollama, the login items and the system's dialogs go through `Doors` (`src/main/hub/wire-hub.ts`), `LoginItem` and `Ask`, which the control line's instance replaces with ones that count. A test must never bring Finder or a browser forward, write over the clipboard or add a login item on the Mac it runs on; anything new of that kind gets a door.
- **The evaluation folder is shared by every build, not under the app's data folder.** A test that deletes saved dictations would delete the real ones unless `WHISPER_FLOW_EVAL_DIR` is set, which `test-app.mjs` and `capture-ui.mjs` both do. Keep it that way in any new script that starts the app.
- **A page that imports a value from `@shared/ipc` bundles the validation library.** Types come from `@shared/ipc`; the few values a page needs (`HISTORY_KEEPS`, `DEFAULT_OVERLAY_PREFS`) come from `@shared/ipc-values`.
- **The dictation key is a setting.** Never write `Fn` into a sentence: take `dictationKeyLabel(status.dictationKey)` for a keycap and `dictationKeySpoken` for VoiceOver. The helper's table comes from `bindingsFor`, and is empty while dictation is paused.
- **What the windows say lives apart from the windows.** There is no DOM in the unit tests, so each page's wording and rules are plain functions with tests (`history-view`, `cleanup-view`, `privacy-view`, `settings-view`, `first-run`, `home-status`), and the components only draw. Put new wording there.
- **Dictated text on a page is marked `data-said`, and a row that is a button is marked `data-row`.** A picture taken for a test blanks the first unless a recording said it, and the control line's summary of the window leaves out the second: neither a picture nor a log may carry what someone said.
- **A window that was never shown fires no focus events.** The tests drive the main window hidden, so a list there must not depend on `onFocus` to choose its first row: the first arrow key does it.
- **Nothing is deleted on the strength of a default.** The history's files are removed at launch only when the settings file itself states "only until I quit" (`SettingsStore.stated`), and saving another setting must not make it state that: an unstated `historyKeep` is left out of the file. A settings file that cannot be read falls back to its defaults, and that default would otherwise delete everything a choice had put on disk. The same question is worth asking of any setting whose default destroys something. And a question that leads to a deletion counts what it deletes, including what it would open first (`HistoryStore.preview`).
- **History and the figures live in the storage process** (`src/main/storage/`, SQLite through `node:sqlite`). Main asks over `birpc` and keeps only the snapshot each answer brings; never make a paste wait for a history write. A write the disk will not take is held there and listed, and main keeps its copy until the snapshot stops naming it (`waiting`), so that a restarted process gets it again. Dictations and counts are separate lanes: one must never hold the other back. History held in memory goes with a process that stops, and the History page says so.
- **What "Save every dictation" saves is decided when the session's recording is let go** (`EvaluationSessions.release`), from how the session ended last, so that Undo and Retry are saved with their text. Delete Everything calls every saving off before it lets any recording go; a save at that moment would write what is being deleted.
- **An answer that is slow is still an answer.** A page that asks again every second and a half must not drop an answer merely because it has asked again since, or it shows nothing while the helper or Ollama is slow. It drops only what is older than what it shows (`InOrder` in `src/renderer/hub/answers.ts`).
- **The strip that moves the window lies over the top of every page.** It is not there for the pointer (`drags-window-over-page`), and every control is marked as not part of it; a control placed near the top needs nothing more. `npm run test:app` presses the ones that are there in a small window.
- **The pages ask for nothing over the network**, and the main process refuses what one asks for all the same (`pageRequestAllowed`). What the app fetches, the main process fetches.
- **A practice is noted as its recording begins.** A dictation into one of the app's own windows is kept out of the history; one that is cancelled or interrupted while the key is held never reaches the point where its destination is read.
- **A signed binary is replaced, never written over.** `scripts/build-helper.mjs` copies the new helper beside the old one and renames it into place. Written over while a helper was still running from it, macOS killed every helper started afterwards ("Code Signature Invalid" in `~/Library/Logs/DiagnosticReports/flow-helper-*.ips`), and the app's log said only `[helper] exited (code none)` (2026-10-04).
- **An app started by a test ends when the test does.** With the control line open the app quits when that line closes, whatever became of the script. On 2026-10-04 a test script died of an error of its own and left its hidden app running for twenty minutes; the next build was made under it. `ps -axo pid,command | grep "whisper-flow --hidden"` finds one that is left.
- **One build at a time.** `test:app`, `pictures`, `smoke` and `pack` all build into `out/`, and a build empties it. `scripts/lib/build-output.mjs` makes a build refuse while an app under test is running from there. Whatever uses `out/` holds it for as long as it does: `pack`, `test:e2e` and `bench:storage` for their whole run, `smoke` for its app run, and `dev` and `smoke:dev` for as long as they run (`scripts/run-from-out.mjs`); a holder is known by its process id and start time. Do not work around it: wait.
- **`isModelReady` reads no file** and is what a status display may poll. Before loading the model, ask `adoptModel`, which reads files nothing vouches for, once. The marker file must stay readable by older builds: they share the models folder.
